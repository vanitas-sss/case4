# Генератор тестовых данных

Скрипт имитирует работу агента и отправляет массив отчётов на `/api/v1/ingest`. Формат отчёта описан в `../contracts/api-examples.json`.

## Запуск

Установите зависимости:

```bash
python -m pip install -r requirements.txt
```

Обычный режим — отправка отчётов каждые пять секунд:

```bash
python generator.py --url http://localhost:8000/api/v1/ingest --interval 5
```

Один отчёт без отправки на сервер:

```bash
python generator.py --dry-run --once
```

Запуск демонстрационного сценария:

```bash
python generator.py --scenario scenario_full_demo.json
```

Заполнение истории метрик за последний час:

```bash
python seed.py --minutes 60
```

## Ручное управление через state.json

Файл перечитывается перед каждым шагом генератора. Его можно менять во время работы:

- `"servers": {"server-02": "offline"}` — сервер перестаёт отправлять отчёты.
- `"containers": {"backend": "stopped"}` — контейнер останавливается. Также поддерживается состояние `restarting`.
- `"cpu_override": {"server-03": 95}` — CPU сервера удерживается около 95%.

## Сценарий full_demo

| Время от старта | Событие |
| --- | --- |
| 1:00 | server-02 перестаёт отправлять отчёты |
| 2:00 | server-02 возвращается |
| 2:30 | контейнер backend останавливается |
| 3:00 | backend снова работает |
| 3:30 | CPU server-03 поднимается до 95% |
| 5:30 | нагрузка CPU возвращается к обычному уровню |

## Типы связей

В `network.links` используются три типа:

- `host` — связь сервера с контейнером;
- `network` — связь контейнера с Docker-сетью;
- `traffic` — связь между контейнерами.

Тип `traffic` дополняет первоначальный план и должен оставаться согласованным с общим API-контрактом.
