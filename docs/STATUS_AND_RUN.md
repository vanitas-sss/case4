# Проверка проекта и порядок совместной работы

Дата проверки: 2026-11-11

## Что уже реализовано

- FastAPI-приложение и версия API `/api/v1`.
- Приём массива отчётов через `POST /api/v1/ingest`.
- Проверка входящих данных Pydantic (`ReportIn`).
- Сохранение хостов, метрик, контейнеров, событий смены статуса, доступности и снимка топологии через SQLAlchemy.
- SQLite с внешними ключами.
- Миграции Alembic.
- Очистка старых метрик, событий и проверок доступности как отдельная функция.
- Генератор тестовых отчётов в `mock-data/`.
- Тесты backend для ingest, базы и контрактов.

## Что ещё не завершено

1. GET-роуты `hosts`, `containers`, `topology`, `availability`, `events`, `alerts`, `summary` пока читают демонстрационные данные из `app/stubs.py`. Они не показывают фактическое содержимое SQLite.
2. Фоновая задача очистки есть как функция, но не подключена к расписанию в lifespan.
3. В `case1_adapter.py` явно указано, что формат отчёта соседнего кейса пока предполагается. Нужен настоящий JSON-пример от команды кейса 1. До получения примера нельзя считать интеграцию подтверждённой.
4. Frontend пока состоит из каталогов-заготовок с `.gitkeep`: нет `package.json`, точки входа React/Vite и страниц.
5. Нет корневого `docker-compose.yml`, Dockerfile backend/frontend и завершённой инструкции развёртывания.
6. Нет отдельного агента в репозитории. Для актуального варианта кейса, где проект является сервисом-приёмником, агент не должен разрабатываться этой командой без отдельного требования.
7. В текущем ingest нет проверки токена источника. Перед подключением к внешней сети нужно согласовать и реализовать аутентификацию источников.

## Запуск backend локально

Требуется Python 3.11+.

Windows PowerShell:

```powershell
cd backend
py -3.11 -m venv .venv
.venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
python -m alembic upgrade head
python -m uvicorn app.main:app --reload
```

Если PowerShell запрещает активацию окружения, можно выполнить:

```powershell
.venv\Scripts\python.exe -m pip install -r requirements.txt
.venv\Scripts\python.exe -m alembic upgrade head
.venv\Scripts\python.exe -m uvicorn app.main:app --reload
```

Открыть:

- Swagger UI: http://127.0.0.1:8000/docs
- Health: http://127.0.0.1:8000/api/v1/health

База по умолчанию: `backend/data/metrics.db`. Переменная `DB_PATH` задаётся относительно каталога backend. Файл базы не нужно коммитить в Git.

## Проверка приёма данных

Оставить backend запущенным. Во втором PowerShell-окне из корня репозитория:

```powershell
cd mock-data
python -m venv .venv
.venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
python generator.py --url http://127.0.0.1:8000/api/v1/ingest --interval 5
```

Генератор отправляет отчёты каждые 5 секунд. В ответе API ожидаются поля `accepted`, `rejected`, `received_at` и `errors`. При успешной отправке `accepted` увеличивается.

Остановить генератор: Ctrl+C.

## Запуск тестов backend

В отдельном терминале:

```powershell
cd backend
.venv\Scripts\Activate.ps1
python -m pytest -q
```

Тесты используют временную SQLite-базу и не должны менять рабочую `backend/data/metrics.db`.

## Проверка API вручную

В Swagger откройте `POST /api/v1/ingest`, нажмите Try it out и отправьте JSON-массив из `backend/examples/ingest.example.json`.

Важно: endpoint принимает именно массив отчётов, даже если отправляется один отчёт. Для одного отчёта формат такой: `[ { ... } ]`, не одиночный объект.

После отправки проверьте `accepted = 1` и `rejected = 0`. GET-эндпоинты на текущем этапе могут показывать демонстрационные данные из `app/stubs.py`, поэтому отсутствие нового хоста в GET-ответе пока не доказывает, что ingest не сохранил данные. Проверять сохранение следует тестом `test_ingest_api_persists_report_to_database` или через SQLite Browser.

## Командные границы и совместимость

- **Backend:** владелец формата `ReportIn`, сохранения данных и HTTP API. Изменения схемы согласовывать через `contracts/api-examples.json`.
- **Команда источника данных (кейс 1):** должна предоставить реальный JSON-пример, описание полей и семантику идентификаторов/связей. После этого обновляется `case1_adapter.py` и добавляются тесты на фактический формат.
- **Frontend:** использовать только поля из API-контракта; не обращаться напрямую к SQLite. Базовый адрес API при локальной разработке: `http://127.0.0.1:8000/api/v1`.
- **Интеграция:** время передавать в ISO 8601 с часовым поясом (предпочтительно UTC, суффикс `Z`). Проценты CPU/RAM/Disk и topology link load — числа от 0 до 100. Списки контейнеров, узлов и связей должны быть массивами JSON.
- **Секреты:** токены и пароли нельзя помещать в `.env.example`, JSON-примеры или Git. В репозитории хранятся только названия переменных и безопасные значения по умолчанию.
