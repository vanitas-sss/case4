# Backend: база данных

## Первый запуск

Из каталога backend установите зависимости и примените миграции:

    python -m pip install -r requirements.txt
    python -m alembic upgrade head
    python -m uvicorn app.main:app --reload

При запуске приложения схема также проверяется и доводится до последней миграции.

## Изменение моделей

После изменения SQLAlchemy-моделей создайте миграцию:

    python -m alembic revision --autogenerate -m "краткое описание изменения"

Перед применением обязательно просмотрите созданный файл в migrations/versions: автогенерация Alembic требует ручной проверки.

Применить миграции:

    python -m alembic upgrade head

Посмотреть текущую версию схемы:

    python -m alembic current

Проверить, не забыта ли миграция после изменения моделей:

    python -m alembic check

Откатить последнюю миграцию:

    python -m alembic downgrade -1

## Хранение данных

Путь к SQLite задаётся переменной DB_PATH в файле .env. По умолчанию используется data/metrics.db. Относительный путь считается от каталога backend.

SQLite работает с включённой проверкой внешних ключей. Времена сохраняются в UTC без информации о часовом поясе, поскольку SQLite не хранит timezone-aware значения.

## Транзакции

Сервис приёма отчётов (ingest_service.process) управляет своей транзакцией: фиксирует весь отчёт целиком либо откатывает его при ошибке.

Функция очистки истории (cleanup_old_records) выполняет удаление и flush, но не вызывает commit: граница транзакции остаётся у вызывающего кода.


## Правила обработки отчётов

- Хост определяется парой source_id + name; контейнер — парой host_id + docker_id.
- Повторный отчёт с тем же timestamp и запоздавший отчёт с более ранним timestamp не меняют текущее состояние и не добавляют дубликаты метрик.
- Если необязательные поля хоста или контейнера переданы как null либо отсутствуют, ранее сохранённые значения IP, image и status сохраняются.
- Для networks у контейнера значение null означает «не обновлять список», а пустой список — «очистить список сетей».
- Пустой список containers не удаляет ранее известные контейнеры.
- network=null означает «топология не передана, оставить предыдущий снимок». Переданный объект network с пустыми nodes и links очищает текущий снимок.
- Метрики и проверки доступности сохраняются как история; при повторном timestamp история не дублируется.


## Подробный запуск и разбор

[Инструкция для Windows, проверки и устройство backend](../docs/BACKEND_GUIDE_RU.md).

По умолчанию heartbeat проверяется каждые 5 секунд: warning после 10 секунд,
offline после 20 секунд, алерт после 30 секунд без новых отчётов.
Существующий `.env` имеет приоритет над этими значениями.
`HEARTBEAT_INTERVAL` описывает ожидаемый интервал источника; генератору интервал
передаётся отдельно через `--interval`.

Сетевые счётчики принимаются в диапазоне 0..9223372036854775807.
Дата отчёта не может опережать часы backend более чем на
`MAX_FUTURE_SKEW_SECONDS` (по умолчанию 60 секунд).
Исторические даты разрешены; историю нужно отправлять по возрастанию времени.

Первый принятый отчёт создаёт событие `source_registered`.
Статус контейнера в API становится `unknown`, если хост не online или сам
контейнер не обновлялся не менее `WARNING_AFTER` секунд. Запись в базе сохраняется;
это не означает, что контейнер точно остановлен. Фильтры и счётчики используют
этот же вычисляемый статус. `dead` входит в число остановленных контейнеров.
